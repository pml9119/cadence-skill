# 跟不懂软件的人怎么问

[`SKILL.md`](SKILL.md) 的 ② 判 推下来的参考。**只在要开口问需求方时读。**

---

## 一条原理

**对方只能做判断题。**

不是因为他水平不够，是因为**开放题的答案需要他已经知道「可能的答案有哪些」**。他不知道系统能长成什么样、不知道别人怎么做、不知道你问这个是为了什么编码决定 —— 所以「你想要什么？」这个问题，他**答不出来是必然的**。

**你的活是替他生成选项，他只负责挑和改。** 一份写着「我猜是这样，改哪儿？」的草案，胜过二十个开放问题。

**这就是为什么 ② 判 的出草案是核心操作**，不是技巧。

---

## 禁止的题型

| 别这么问 | 为什么 | 改成 |
|---|---|---|
| 「你想要什么功能？」 | 要求他做产品设计 | 出草案：「我猜是这三个功能，删哪个？」 |
| 「这个字段填什么？」 | 要求他做数据建模 | 给一张填好的示例：「像这样填，对吗？」 |
| 「优先级怎么排？」 | 要求他维护 backlog | 一次推三个动作：「这三件，先做哪个？」 |
| 「什么叫『做得好』？」 | 要求他给验收标准 | 「我看到 XXX 就算做完了，够不够？」 |
| 「你需要什么报表？」 | 要求他懂查询模型 | 直接画一份样例报表给他看 |
| 「这个术语你懂吗？」 | 让他承认不懂 | 用他的原词复述一遍，看他纠正不纠正 |

**共同点：这些问题都在要求他做本该由 agent 做的活。** 一个非 IT 的人被问到这些，只有两条路 —— 沉默，或者随便说一个（而随便说的那个会被当成需求记录下来，然后在三个月后变成一个没人要的功能）。

---

## 四个改问法

**1. 开放题 → 二选一。**
「你想要哪种？」→「A 和 B，哪个更像你要的？」
二选一他一定答得出来，因为两个选项都是**具体的东西**。

**2. 开放题 → 给样例让他挑。**
「筛选条件要哪些？」→ 拿三份别人做过的同类界面（或你现画的三张草图），「哪个最接近？」
**挑比想容易得多。**

**3. 空手问 → 带草案问。**
「一条记录长什么样？」→ 出一张填了示例值的表，「我填了一行，哪里不对？」
**他改一个具体的东西，比从零描述容易一百倍。** 这是本 skill 最高频的操作。

**4. 抽象题 → 场景题。**
「团体画像要哪些维度？」→「上周三你带的那个组，你会怎么描述它？谁在里面、几个人、什么状况？」
**从具体事件里提取维度，比凭空枚举维度容易。**

## 五个可以照抄的题干

见面或对话时直接照搬，替换 `<>` 里的内容。

1. **复述开场**：「我听下来是这样：`<用他的原词复述一遍>`。哪里说错了？」
2. **草案开场**：「我按理解出了一版 `<表 / 页面 / 流程>`，一共 `<n>` 处。你只需看标黄的地方，说对或不对。」
3. **场景提取**：「你上次 `<做这件事>` 是什么时候？当时具体怎么弄的？」
4. **优先级**：「这三件里，如果只能先做一件，哪件？」
5. **收口**：「这轮我记了 `<n>` 条，一条没漏吧？下轮我看 `<n>` 条。」

**第 5 条每轮都要问。** 它是唯一的防漏机制 —— agent 的收口数错了，只有他能发现。

---

## 复述的规矩

**复述时用他的原词，不要换成你的术语。**

- 他说「要能看出来谁做得好」→ 复述「要能看出来谁做得好」，**不要**复述成「需要绩效评估功能」
- 他用错词也不要纠正他，先记下来；**同一个词他用了两次以上，才值得问一句**

**为什么**：把他的话翻译成术语再让他确认，等于让他**确认你的翻译** —— 他会因为不确定而点头。等他看到产品再说「不是这个意思」时，代码已经写完了。

**术语翻译留到 ③ 译 那一步做，而且留锚点。**

## 术语禁用表

对方是非 IT 专业人员时，这些词一律换掉：

| 别说 | 说 |
|---|---|
| backlog / 待办列表 | 还没做的清单 |
| sprint / 迭代 | 这一批 |
| user story / 用户故事 | 这件事 |
| API / 接口 | 两个东西怎么对上 |
| 字段 / schema | 这一栏填什么 |
| 部署 / 上线 | 让别人能打开用 |
| 重构 | 里面重写一遍，外面看着一样 |
| spec / 规格 | 要做成什么样 |
| WIP / 在制品 | 同时在做几件 |
| 里程碑 | 到哪天、做完什么样算过 |

**说漏了一个术语，对方不会问「这是什么」—— 他会点头。** 然后你们对同一句话的理解从此分岔。

## 什么时候该停

**这三个信号说明问法不对，立刻退回上一条改问法（通常是退回「带草案」）。**

| 信号 | 意思 |
|---|---|
| 他沉默，或说「都行」「你决定吧」 | 问题超出他的判断范围。**这时候的「都行」不是授权，是弃权** —— 你替他决定的那个，他事后会不认 |
| 他开始用你的术语，但用错了 | 他在猜你想听什么。**停下来，用他的词重问** |
| 他开始讲别的（无关的事、抱怨、往事） | 问题没落到他关心的事上。**跟着他走一段**，那里往往有真需求 |

**「你决定吧」出现时不要接着做。** 换成一个具体二选一，或者拿一份草案回来。**核心原则「弃权即未定」**：弃权不是授权，替他做的决定等于需求未定就开工。

## 一次问多少

**数字（一批 ≤ 5 条、其中 ≥ 4 条是判断题）见 [`SKILL.md`](SKILL.md) 的 ③ 译 第 5 条** —— 这里只讲怎么配比。

**超过两条需要他从零描述，说明草案出得不够。** 这一条比数量更重要：5 条里哪怕只有 2 条是开放题，他也会在那 2 条上弃权，然后连着把其余 3 条一起「都行」掉。
