# cadence · 节奏

> **Scrumban 式的项目调度层。** 它同时扮演**产品经理**（做什么、先做哪个）和**项目经理**（几个在做、卡在哪、什么时候算完）。

它架在 matt pocock 的工程 skills 之上：那些 skills 说每一步**怎么做**（采访、spec、票、实现、评审），cadence 说**做什么、什么时候做、同时做几个**。

**它挡的失败是「没人读过的代码山」。** 它假设一个人同时管方向又管进度 —— 这里的"团队"就是你和 N 个 agent。

当前版本：**v7**（版本历史即 git 提交历史）。

---

## 它借了什么，去了什么

**从 Scrumban 借来三件**：**看板**（六列，票不跳列）· **在制品上限**（N）· **拉动**（「待开工」少于阈值才从「发现」拉票）。

**去掉**：时间盒、承诺、故事点、速度。

**加上**：三类 cadence 事件 —— 每日看一个数、每周回顾、触发式补充。

---

## 两个入口

数字 0–5 被看板六列占用了，所以两个入口**用名字，不占编号**：

| 入口 | 搞清什么 | 什么时候跑 |
|---|---|---|
| **盘点**（`inventory`） | **手上有什么**：功能全清单 + 入口总表 | 第一次接手项目**必跑**；之后每个里程碑过闸、每周复盘**重跑** |
| **收原话**（`raw`） | **对方要什么**：收原话 → 判 → 译 | 之后**每一轮** —— 大部分时间在这里 |

**盘点是一道入口闸门**：没盘过、或过期（超过一个里程碑或一周，先到者为准）→ 不许往下走任何一步。
**收原话不能替盘点** —— 收得再全也只是「对方要什么」，不知道「手上有什么」就没有东西可以对照，漏掉的需求没人能发现。

---

## 全链路

**①—④ 是「进来之前」的四站**（收原话 → 判 → 译 → 放行）；**⑤ 就是方向层的 D1/D2**（排优先级、定里程碑），两个名字指同一件事：

```
盘点 ── 只跑一次（之后按里程碑/每周重跑）
     盘出：入口总表 · 功能全清单 · 漂移清单  →  .intent/inventory/

                    ↓ 盘完之后

① 收原话 ─⇥ 换 context ⇥─→ ② 判 三类判断 ──→ ③ 译 产品语言 ──→ ④ 放行 闸 S → 闸 T
  原文只读 · 逐条标可信度 · 收口数数         需求条目带原话锚点 · 批不过 5 条

                              ↓ 带原话锚点的需求条目

方向层 ── 决定做什么
   ⑤ 排：优先级（D1） → 里程碑（D2）
   需求：模糊进迷雾 · 改动走变更（只换范围，不动在制品）
                              │
          ═══ 交界 ═══ 交出一张排好序的候选清单
                              │
流动层 ── 决定怎么流动
   0 迷雾 → 1 发现 ─闸 S→闸 T→ 2 待开工 → 3 进行中 → 4 待验收 ─闸 V→ 5 已完成
                                         在制品 ≤ N           （你裁决）
```

> **两套编号互不相干**：①②③④ 是「进来之前」的四站，0–5 是看板六列。

**两层职责分开**，各自落盘：

| 层 | 回答 | 落盘在 |
|---|---|---|
| **方向层** | 先做哪个 · 到哪算到 · 怎么讲给人听 | `docs/agents/direction.md` |
| **流动层** | 同时跑多少 · 卡在哪 · 谁验收 · 什么时候复盘 | `docs/agents/flow.md` |

**三道闸门必须由人过**：闸 S、闸 T（从「发现」放行）、闸 V（验收）。
需求方看不懂 spec 时，闸 S 换成 `/prototype` —— **原型就是需求方的 spec**。

---

## 落盘：谁是谁的真相源

| 存什么 | 放哪 | 腐烂方式 |
|---|---|---|
| **原料**（盘点结果、原话、需求条目） | `.intent/`（**仓库内，跟代码一起进版本库**） | 配置会过期，**原料只会丢** |
| **配置**（优先级、里程碑、依赖表、N、阈值） | `docs/agents/direction.md`、`docs/agents/flow.md` | 会过期 |
| **决策账本** | **只认一处**，由 `flow.md` 指明 | **变成两份就失效** |

`drift.md` 只有一份 —— 盘点的「与旧自述冲突」和收原话的「文档说 A、原话是 B」是同一件事。

## 本仓库装了什么

这是**两个配套 skill**：

| 目录 | skill | 作用 |
|---|---|---|
| `cadence/` | `cadence` | 调度层本体：两个入口 + 方向层（D1 优先级、D2 里程碑、D3 汇报、D4 审批）+ 流动层（在制品上限、六列看板、三道闸门、全局依赖表、节奏、度量） |
| `setup-cadence/` | `setup-cadence` | 安装器：在具体仓库里搭出 cadence 假设的仓库级配置。**首次使用 cadence 前跑一次** |

`setup-cadence` 标了 `disable-model-invocation: true` —— 它是给人主动调用的，不会被模型自行触发。

`cadence/SKILL.md` 是主入口（只读它就能跑完全程）；其余**按分支读**：

| 文件 | 什么时候读 |
|---|---|
| `cadence/DOC-INTAKE.md` | 原料是一份文档（尤其**半成品稿**）：乱的是可信度，不是结构 |
| `cadence/CHAT-INTAKE.md` | 微信 / 飞书聊天记录：导出工具、五种真需求句式、图片语音怎么登记 |
| `cadence/PROBING.md` | 要开口问不懂软件的需求方：禁用题型、四个改问法、术语禁用表、三个停手信号 |
| `cadence/FLOW-REFERENCE.md` | 挂载点表（哪一列用哪个 skill）、阶段边界、反屎山四层、并行 agent 的四个副作用 |
| `cadence/MAINTAINING.md` | 一个周期之后 / 怀疑这套东西在腐烂 / 换仓库搭环境 |
| `cadence/templates/` | 要落盘某个产出时的 6 份填空骨架 |

## 安装

把两个目录放进你的 skills 目录，**目录名保持 `cadence` 与 `setup-cadence`**（skill 名由目录里的 `SKILL.md` frontmatter 决定）：

```bash
git clone https://github.com/pml9119/cadence-skill.git
cp -r cadence-skill/cadence cadence-skill/setup-cadence ~/.agents/skills/
```

Claude Code 的 skills 目录是 `~/.claude/skills/`；用哪个取决于你的 agent 运行时。Windows 上对应 `C:\Users\<你>\.agents\skills\`。

## 首次使用顺序（D0）

| 顺序 | 做什么 | 为什么是这个顺序 |
|---|---|---|
| 1 | `/setup-matt-pocock-skills` | `/code-review` 依赖它产出的 `docs/agents/issue-tracker.md` |
| 2 | `/setup-cadence` | 本仓库的安装器 |
| 3 | `/setup-pre-commit` + `/git-guardrails-claude-code` | 提交闸门要在有代码之前立好 |
| 4 | `/setup-ts-deep-modules`（TS 项目） | 物理边界，同上 |
| 5 | `/wayfinder` | 真正开始 |

`/setup-cadence` 的前置是 `docs/agents/issue-tracker.md` **必须已存在** —— cadence **不定义** tracker，它只读。

第 3、4 步提前做的理由：**边界要在有代码之前立好。等屎山出来了再立，成本是十倍。**

## 度量怎么跑

`setup-cadence/flow-metrics.mjs` 会被拷到你仓库约定的工具目录（常见 `scripts/` 或 `tools/`），它靠 git 历史算周期时间和待验收年龄：

```bash
node scripts/flow-metrics.mjs          # 文本报告
node scripts/flow-metrics.mjs --json   # 结构化输出
node scripts/flow-metrics.mjs --help   # 参数与更多选项
```

给五个读数：**待验收最老年龄**（超过阈值就停手）、**周期时间**（ready → done）、**待验收积压周趋势**（它涨说明 N 填大了）、**返工次数**（返工变多时，停的是新开工）、**预计完成日**（给区间，不给单点）。
**退回重做的票，周期时间从重新进「进行中」起算** —— 所以**状态变更要单独提交一次**，否则这些数字算不出来。

`setup-cadence/selftest.ps1` 不是种子文件：它在一个临时 git 仓上验证 `flow-metrics.mjs` 的解析与统计，带 **13 条断言**（不符即退出码 1）。怀疑度量数字不对时跑它。

> **改 `selftest.ps1` 时保持 ASCII 注释**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 文件按 ANSI/GBK 解码，中文注释的字节会吞掉下一行代码。

## 一条纪律

**同一条规矩只写一遍。** 重述会让两处各自漂移。要知道某个工程 skill 是什么，让你的 agent 跑 `/ask-matt`。

同一条纪律也管本仓库自己：**改完源文件要同步到运行时副本**（`~/.dsh/skills` 或你的 skills 目录），否则两处各自漂移 —— 见 `cadence/MAINTAINING.md` 的「保持活性」。
